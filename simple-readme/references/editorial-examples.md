# 情報の粒度と分離の判断例

迷った箇所に近い例だけ参照する。例の見出しや章数をそのまま使う必要はない。

## 同じ情報でも置き場は読み手で変わる

| 情報 | READMEに残す範囲 | 詳細へ分ける範囲 |
| --- | --- | --- |
| ログイン | 誰がどの方法で入るか。使い始めるための前提 | OAuth設定、ロール照合の実装、監査時の経緯 |
| 環境変数 | 最短実行に必要なものと設定例へのリンク | 全変数、外部連携ごとの取得手順 |
| CLIオプション | 代表的な利用例とヘルプの入口 | 全オプション表、特殊ケースの組み合わせ |
| ライブラリAPI | インストール、最小利用例、主要な制約 | 全API、拡張方法、内部設計 |
| データ | 入手先、形式、最小サンプル、利用条件 | 全列定義、前処理の全分岐、搬入履歴 |
| 実験 | 何を確かめるか、再現の入口、必要な計算資源 | 全実験条件、ログ、比較表、失敗した試行 |
| ハードウェア | 対応機種、必要部品、動作・安全上不可欠な前提 | 回路解説、調整手順、修理記録 |
| 文書集 | 誰向けか、読む順序、主要資料へのリンク | 執筆方針、生成処理、過去版の変更理由 |
| デプロイ | 配布型ツールではリリースの入手先、サービスでは利用URL | インフラ構築、認証情報、バックアップ、障害対応 |
| ディレクトリ | 主要な置き場が分かれば十分な短いツリー | 全ファイルや内部関数の一覧 |

「技術者だけが読む情報」と「エージェントだけが読む情報」を混同しない。インストール、ビルド、公開APIの例は人間の開発者にも必要。特定のガード関数を必ず通す指示や、更新時に読むファイルの対応表は通常エージェント用文書へ委ねる。

## 文を短くするだけでは解決しない例

### 運営アプリ

元の内容：各画面の全操作、案件スコープのクエリ実装、運用APIのcurl、ローカル起動、本番設定が1ページに混在。

判断：

- READMEは「誰のためのアプリか」「代表的な画面」「構成」「技術」「空の環境からの起動」に絞る。
- 本番設定と管理APIは運用ページへ。クエリの必須ガードは既存のエージェント用規約に委ねる。
- ローカル起動の前提や、データ投入が既存データを上書きすることは利用例の近くに残す。
- 内部関数や実装済み機能の網羅表を、短い箇条書きに変えてREADMEに残すだけでは不十分。

### CLI

元の内容：引数パーサーの内部構造、40オプション、プラグイン開発、リリース手順だけで200行。

判断：

- 説明の直後にインストールと代表コマンド、その出力例を置く。
- 全オプションは`--help`または既存リファレンスへ。プラグイン作者向けの文書は別ページへ。
- 入力を書き換えるツールなら既存のdry-runを先に示す。dry-run機能がなければ作らない。
- Webの技術スタック表、ログイン画面、DB構成図を追加しない。

### ライブラリ

元の内容：内部クラスを網羅するが、利用者が何をimportするか分からない。

判断：

- 対応ランタイム、実在する公開APIでの小さな例、期待される戻り値、重要な制約を優先する。
- モジュールの内部依存関係より、入出力や拡張点が分かる説明を選ぶ。
- パッケージが未公開なら、公開済みと誤認させるインストールコマンドを作らない。
- 貢献者向けの開発手順と利用者向けの導入手順を混ぜない。

### データ分析・研究

元の内容：実験ログが先頭に続き、データの入手条件が最後にある。

判断：

- 目的、入力データの入手条件、実行環境、再現コマンド、生成物を入口にする。
- 計算時間、GPUの要否、非公開データの別途取得は、再現できるかの判断に必要なら残す。
- ライセンスや論文引用は人が必要とする情報なので、短くするために削らない。
- 既存の小さなサンプルがあればそれを先に示す。全件の高額な計算を検証のために始めない。

### 文書・教材リポジトリ

元の内容：生成スクリプトと執筆規約が中心で、読むべき本文が見つからない。

判断：

- 対象読者、読む順序、主要な本文や公開済み資料へのリンクを先に置く。
- ローカルビルドは貢献者向けの節か別ページへ。閲覧に不要なNode.jsやPythonの導入を最初に要求しない。
- 数本の独立した文書で十分なら図は省く。章の前提関係が理解を助ける場合だけ依存図を作る。

## ページを分けすぎない判断

- 6行の補足のために新ページを作るより、短い小節か既存ページへのリンクを使う。
- 同じ担当者が同じ作業で必要とする設定はまとめる。1環境変数につき1ページにはしない。
- 新しい「詳細」ページが元のREADMEとほぼ同じなら、読者の用事で再整理する。
- 移動する情報に既存の詳細ページがあるか調べ、複製する前に統合を検討する。
